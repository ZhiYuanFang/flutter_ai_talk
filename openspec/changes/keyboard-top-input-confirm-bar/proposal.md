# Proposal: keyboard-top-input-confirm-bar

## Why

当前项目存在多个输入入口（首页文本输入、登录/注册、设置弹窗、记录编辑弹层等），在移动端聚焦输入框时常出现页面被键盘顶起、视觉跳动和操作路径不一致的问题。随着输入入口持续增多，需要统一一套输入交互规范，确保“聚焦后界面稳定、输入与确认路径一致、业务回填可控”。

## What Changes

- 新增统一的“键盘上方输入确认条”交互：当任意受管控输入框聚焦时，在键盘上方展示输入文本区域与右侧“确定”按钮。
- 统一输入提交语义：点击“确定”后，将确认内容回填到目标输入框，并触发该输入场景既有提交逻辑（如登录、提交记录、确认文本等）。
- 统一键盘与布局策略：在受影响页面/弹层中，避免聚焦时主界面被键盘整体顶起，改为由输入确认条承接输入与提交。
- 保留现有输入能力：不移除既有输入框、校验规则、只读态、密码态、业务按钮和提交接口。
- 建立输入场景覆盖清单与验收口径，确保全量输入入口具备一致行为。

## Capabilities

### New Capabilities

- `keyboard-top-input-confirm-bar`: 定义全局输入焦点接管、键盘上方输入确认条展示、确认回填与提交触发的统一行为规范。

### Modified Capabilities

- （无）

## Impact

- 受影响代码主要位于 Flutter UI 层输入相关页面与弹层，包括但不限于 `home_screen`、`login_screen`、`register_screen`、`settings_screen`、`home_history_edit_sheet`、`home_number_event_sheet`、`baby_bind_screen`、`baby_profile_editor`。
- 可能涉及通用组件与应用壳层（如键盘收起作用域、底部弹层适配、全局输入桥接状态）。
- 不引入后端 API 变更；重点影响前端交互一致性、可用性与移动端输入体验。
- 需补充/调整 UI 交互测试与关键输入路径回归测试。
