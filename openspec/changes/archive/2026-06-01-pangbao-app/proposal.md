## 背景与动机

照护者需要在不便操作表单时，快速以自然语言记录或调整母婴喂养等相关事件。**胖宝**将自然语言交给服务端解析并执行业务，同时在客户端展示历史与趋势，降低操作成本并以后端为单一事实来源。本变更建立面向 **Android、iOS、Web** 的 Flutter 客户端；首阶段（M1）以**完整页面与导航 + 接近真实接口形态的假数据**为主。

## 变更内容

- 新建 Flutter 应用 **胖宝**，目标平台为 **Android、iOS、Web**。
- **认证**：三端均实现**真实微信登录**（移动端走 SDK 能力；Web 端走微信**网站应用 / 网页授权**等官方要求的方式）。登录页在主登录操作下方展示 **「请阅读并同意隐私政策」** 且可点击；隐私内容在应用内通过 **WebView**（移动端）或 Web 端等效的**页内嵌入**方式打开配置 URL。
- **主页**：主输入区在移动端为**按住说话、松手结束**，经原生或系统支持的能力**语音转文字**，仅上传**文本**；Web 端**不使用语音**，改为**文本输入 + 提交**。其上方为**历史记录区**：数据来自服务端契约（M1 可用 Mock）；**时间倒序展示，最新一条在底部**；自下而上**渐隐**，越往上**字号越小**（在无障碍最小字号约束内）。通过 **SSE**（M1 可用等价 Mock 流）接收服务端推送的最新记录并更新列表。
- **趋势中心**（二级页）：入口位于主输入区**右上方附近**（「趋势」）。先从服务端获取**当前有哪些可趋势化的事件**（M1 为 Mock 列表），再为每个事件展示**按时间范围**的趋势图（Mock 序列）。
- **设置中心**（二级页）：入口在主页**右上角**（「设置」）。展示账户下**唯一绑定宝宝**的信息；提供**隐私政策**（同登录，应用内打开 URL）、**切换账号**、**注销账户**（M1 可做 UI 与占位流程）。
- **主题**：默认根据宝宝**性别**着色（男 → 深蓝，女 → 红）；用户可在设置中**自定义背景色**（设置后优先于性别默认背景）。
- **版本更新**：**iOS** 提示并跳转 **App Store** 应用页；**Android** 在 **App 内下载并安装**新包；**Web** 检测到新版本时**提示刷新或重新进入**（不做 APK 安装）。
- **M1 验收**：各页面绘制完成、页面间跳转通畅；接口形态用 **Mock/假数据**；客户端**不得**写死喂养事件类型全量枚举，列表与趋势键名来自 Mock 的「服务端」响应。

## 能力划分

### 新增能力（每个对应 `specs/<kebab-name>/spec.md`）

- `auth-wechat-privacy`：三端微信登录、登录页体验、隐私提示与应用内打开政策 URL。
- `home-input-history-sse`：主页布局、按平台的输入方式（语音+转写 vs 文本）、历史展示规则、SSE 消费（可 Mock）。
- `trends-center`：趋势入口、服务端驱动的事件列表、按时间范围的趋势图。
- `settings-center`：宝宝摘要、隐私入口、账号类操作、主题与自定义背景。
- `app-versioning`：跨端版本检测与提示；iOS 跳转商店；Android 应用内安装；Web 刷新引导。

### 变更的既有能力

- 无（本仓库为全新 OpenSpec 能力集，无既有 `openspec/specs/` 能力需改）。

## 影响范围

- **新增** Flutter 工程及 Android / iOS / Web 平台配置。
- **依赖**：微信各端 SDK 与 Web OAuth 配置；移动端语音识别插件或系统能力；政策页 WebView（Web 为 iframe 等）；SSE 客户端；图表库；Android 安装流程涉及的权限与 FileProvider 等（真机安装阶段）。
- **后端契约**（后续里程碑）：鉴权令牌、文本指令接口、历史拉取、SSE 通道、趋势接口、版本清单——M1 仅需稳定的 Mock 数据结构，不要求真实服务已上线。
