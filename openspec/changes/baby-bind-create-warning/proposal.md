## Why

当前“宝宝信息绑定”页在“创建新宝宝”路径缺少风险提示，容易让已有家庭宝宝被重复创建，导致家庭内协同混乱与后续数据割裂。同时页面文案“绑定宝宝ID”不符合产品语义，用户感知成本较高。

## What Changes

- 在“创建新宝宝”操作前增加强提醒：告知用户若家人已创建宝宝，应优先使用“绑定宝宝”而不是创建新宝宝。
- 将绑定入口相关文案从“绑定宝宝ID”统一调整为“绑定宝宝”。
- 保持现有绑定/创建 API 行为不变，仅调整前端交互与文案引导。

## Capabilities

### New Capabilities
- `baby-binding-flow`: 规范宝宝绑定页在“创建新宝宝”前的提醒流程与绑定文案一致性。

### Modified Capabilities
- （无）

## Impact

- 影响界面与交互：`app/lib/ui/baby_bind_screen.dart`。
- 影响产品文案一致性：设置中心与绑定页中的“绑定宝宝ID”展示文本。
- 不涉及后端 API、数据模型与依赖变更。
