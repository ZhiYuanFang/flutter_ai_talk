# home-immersive-header-no-appbar 设计

## Context

当前主页在 `Scaffold.appBar` 使用全局 `AppBarTheme`，视觉上形成独立顶栏色块；这与目标参考图的「顶部控件漂浮在内容背景上」不一致。现有主页同时承载绑定横幅、今日摘要、历史列表、WS 状态横幅、底部输入模块，属于高耦合页面，改动需控制回归风险。

约束：

- 不改变历史列表与输入模块数据流（SSE/WS、语音、按钮输入）。
- 趋势与设置入口必须继续保持在主页顶部可达。
- 顶部区域与内容区必须一体化，不得再出现明显分色块。


## Goals / Non-Goals

**Goals:**

- 移除主页标准 `AppBar`，采用页面内沉浸式头部行。
- 让状态栏下方头部控件与内容共享背景语义，形成无缝衔接。
- 保持趋势/设置入口可达，交互语义不变。
- 在浅色与深色 shell 下均保持可读与层次。

**Non-Goals:**

- 不重构历史列表结构（不切换为新滚动架构）。
- 不调整底部输入模块功能与行为。
- 不引入新的业务接口或状态机。

## Decisions

### 1) 头部形态：移除 `Scaffold.appBar`，改为 `SafeArea` 内自绘头部行

- 方案：在 `body` 顶部放置 `HomeImmersiveHeader`（或等价内联布局），承载标题和右侧操作入口。
- 原因：可以完全消除 `AppBarTheme` 造成的独立色块；布局控制粒度更高。
- 备选对比：
  - 透明 `AppBar`：改动小，但仍受 `Scaffold`/`AppBar` 交互层影响，容易出现滚动态与阴影残留。
  - `SliverAppBar`：适合重构为 `CustomScrollView`，但对当前首页耦合过重，超出本次范围。

### 2) 背景策略：头部与内容使用统一 shell 背景语义

- 方案：头部容器不使用独立底色块，背景与页面外壳一致；通过间距与字体权重建立层级。
- 原因：实现参考图中的「融为一体」观感，避免硬分割线。
- 备选对比：给头部加半透明底板会再次制造“假 AppBar”。

### 3) 导航入口迁移：趋势/设置从 `AppBar.actions` 迁到沉浸式头部右侧

- 方案：保持原有路由行为（`/trends`、`/settings`）与按钮语义，仅迁移承载位置。
- 原因：在移除 `AppBar` 后仍保证入口稳定可达，减少用户学习成本。

### 4) 垂直节奏：定义头部到首块内容的固定呼吸间距

- 方案：头部底部至首个内容块（绑定横幅或今日摘要）维持紧凑间距（如 8–12dp 量级），并在无首块内容时保持一致 top padding。
- 原因：解决“头部悬空”或“贴得过紧”导致的视觉跳变。

## Risks / Trade-offs

- [风险] 顶部点击热区靠近状态栏，可能误触或压缩可点面积  
  → [缓解] 保证最小触控尺寸与 `SafeArea` 内边距。
- [风险] 不同主题下标题/图标对比不足  
  → [缓解] 统一从 `AppVisualTokens.onShell` 或对比兜底色取前景色。
- [风险] 迁移头部后可能影响现有顶部组件（绑定横幅/今日摘要）的纵向布局  
  → [缓解] 将“头部 + 首块内容间距”收敛为常量并覆盖空态/有数据态回归。

## Migration Plan

1. 新增沉浸式头部组件并接入主页布局。
2. 移除主页 `Scaffold.appBar` 与对应 `actions`。
3. 将趋势/设置入口迁移到新头部并复用原回调。
4. 调整首块内容顶部间距，覆盖有绑定横幅与无绑定横幅两种路径。
5. 自测浅色/深色 shell、空态/有记录、登录/未登录、WS 断开横幅并回归。

回滚策略：保留单点回退路径（恢复 `Scaffold.appBar` 与旧 `actions` 布局），不涉及数据迁移。
