# remember-select-event-in-form 设计

## Context

当前趋势中心在 `TrendsScreen` 中通过 `_syncSelection()` 仅保证“当前选中项为合法叶子”，并在无选中或失效时回退到第一个叶子。该行为满足可用性，但无法保留用户上次分析上下文。

现有项目已具备本地记忆模式（如日期范围记忆、事件 number 记忆），均基于 `SharedPreferences`，因此本次可复用同一持久化策略，降低引入成本与一致性风险。

约束：
- 事件目录仍由现有 `eventCatalogProvider` 驱动；
- 趋势页仍仅允许合法叶子事件；
- 目录刷新后若记忆事件失效，必须可自动回退并触发拉数；
- 不改变日期范围记忆与趋势序列 API 契约。

## Goals / Non-Goals

**Goals:**
- 进入趋势中心时优先恢复上次选中的合法叶子事件。
- 用户切换事件后立即更新本地记忆。
- 记忆失效时稳定回退到第一个合法叶子，并保持现有拉数时序正确。
- 与现有存储实现风格一致，便于维护与测试。

**Non-Goals:**
- 不改动事件目录服务端协议与字段。
- 不引入跨页面共享“全局当前事件”状态。
- 不改变趋势图渲染逻辑、日期范围逻辑或登录蒙层逻辑。

## Decisions

1. **新增独立存储 `TrendsSelectedEventStore`（SharedPreferences）**
   - 决策：新增单键存储最近一次趋势事件选择（如 `trends_selected_event_v1`）。
   - 原因：与 `TrendsDateRangeStore`、`EventNumberMemoryStore` 一致，简单、低风险。
   - 备选：复用现有任一 store。未采纳，因语义耦合不清且后续演进成本高。

2. **初始化选中流程改为“记忆优先，叶子兜底”**
   - 决策：页面初始化在目录可用后先读取记忆；若记忆 ID 在当前 `leafEvents(requireValidEventType: true)` 中有效，则设为选中；否则走既有第一个叶子兜底。
   - 原因：满足“默认上次选择事件”的用户目标，同时保持原有兜底稳定性。
   - 备选：直接依赖 `_syncSelection()` 后再二次覆盖。未采纳，因可能造成额外状态抖动与重复拉数。

3. **用户显式切换事件即写记忆**
   - 决策：在事件选择器确认新事件后，先更新 `_selectedKey` 并写入 store，再触发趋势数据加载。
   - 原因：确保“下次进入默认上次选择”语义在每次交互后立即生效。
   - 备选：退出页面时统一写入。未采纳，因异常退出可能丢失最近选择。

4. **目录刷新后的失效处理沿用现有 `_syncSelection()` 主体逻辑并补写记忆**
   - 决策：当刷新导致当前选中失效并回退时，同步更新本地记忆为新选中项。
   - 原因：避免本地持久化长期保留无效 ID，减少下次进入时无效判断分支。
   - 备选：仅内存回退，不改记忆。未采纳，因会造成反复“读到失效值再回退”。

## Risks / Trade-offs

- [风险] 初始化阶段读取记忆、加载目录与远端刷新并发，可能导致重复拉数。  
  → 缓解：保持现有 `_seriesLoadSeq` 防抖语义；仅在选中值实际变化时触发加载。

- [风险] 历史记忆值与目录 ID 归一化规则不一致（如字符串/数字）。  
  → 缓解：沿用现有 `leafEvents` + `id` 精确匹配策略；必要时统一通过目录已有归一化工具比较。

- [权衡] 新增一个轻量 store 会增加少量配置文件。  
  → 收益：语义隔离清晰，后续维护与回归测试成本更低。

## Migration Plan

1. 新增趋势事件选择记忆 store，并定义键名版本号（`_v1`）。
2. 调整 `TrendsScreen` 初始化与事件切换流程，接入读写逻辑。
3. 增补目录刷新后回退时的记忆更新。
4. 完成手动回归：首次进入、二次进入恢复、记忆失效回退、远端刷新变更。
5. 回滚策略：移除新 store 读写调用即可回退到“默认第一个叶子”的旧行为；保留本地键不会影响功能。

## Open Questions

- 是否需要在“用户主动清空缓存/退出登录”时同步清理趋势事件记忆？（当前可不做，因失效自动回退）
- 记忆是否需区分设备（`deviceNo`）维度？（当前按现状先做全局，后续若有多设备冲突再扩展键名）
