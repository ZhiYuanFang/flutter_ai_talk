## Why

间隔预测用全天间隔一起做加权中位。上次落在傍晚时，过夜约 12 小时的间隔一天只有一条，白天短间隔条数更多，中位数仍是约 3 小时，下一次被推到历史上这个钟点从不会发生的时刻。同档样本已经够门槛时，应只让「从同一时段出发」的间隔投票。

## What Changes

- 锚点时段桶内有效间隔不少于 2 时，加权中位只使用起点落在该桶的间隔；相邻桶与更远桶不得进入这一轮。
- 同档不足 2、但同档加相邻档不少于 2 时，仍用同档与相邻档（权重 1.0 / 0.6）做加权中位。
- 再不足时维持现有全桶等权回退；仍不足则沿用种子间隔或不可预测。
- 公式保持 `nextAt = lastAt + interval`。不改为按历史钟点簇吸附。
- 不改时长/用量线、预约约定、15 分钟过滤、月龄半衰期、回忆种子与 lastAt 缓存回退。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `event-interval-prediction`：真样本达标时的加权中位改为同锚点时段桶优先；同档样本不少于 2 时不得用其它桶的短间隔压过该档间隔（含过夜长间隔）。

## Impact

- 代码：`app/lib/data/event_next_predictor.dart` 中间隔样本收集与中位入口。`nextAt` 数值会变，既有指纹路径可能重同步 imminent，无新 HTTP / Go 契约。
- 规格：未归档的 `event-last-at-cache` 已改同一 Requirement 的 lastAt 回退。本变更在该语义之上收紧投票范围，并同步该兄弟 delta 的中位场景，避免后归档把同档投票盖回「同档加相邻一起算」。
- 无 Android 原生改动，无新测试文件。
