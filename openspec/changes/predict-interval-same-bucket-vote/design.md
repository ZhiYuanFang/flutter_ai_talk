## Context

`predictNextForEventKey` 用 `nextAt = lastAt + 加权中位间隔`。间隔样本是相邻真发生的时间差（短于 15 分钟丢弃）。锚点桶是 `timeOfDayBucket(lastAt)`，样本桶是这段间隔的起点 `timeOfDayBucket(times[i-1])`。六档：0–6、6–9、9–12、12–15、15–18、18–24；0 与 5 相邻。

现有 `strictBuckets: true` 仍收全部样本，只把同档权重设为 1.0、相邻 0.6、其余 0.2。门闸是权重大于 0 的条数不少于 2。傍晚锚点下，一天里多条白天短间隔的权重合计可以超过唯一一条过夜长间隔，加权中位停在短间隔。样本再多，这个每天的票型也不变。

未归档变更 `event-last-at-cache` 已改同一 Requirement 的 lastAt 回退（窗口未命中时用事件最近发生缓存，不得把缓存合成伪记录）。本变更不改那条回退。

## Goals / Non-Goals

**Goals:**

- 同档有效间隔不少于 2 时，中位数只从该档起点的间隔里取，过夜长间隔在傍晚锚点下成为该轮的全部票。
- 同档不足时逐级放宽：同档+相邻，然后全桶等权，然后种子间隔，然后不可预测。
- 公式仍是 `nextAt = lastAt + interval`。

**Non-Goals:**

- 不按历史钟点簇把落点吸到「平时那个钟点」。
- 不改桶边界、半衰期、15 分钟过滤、预约 `nextAt`、duration/amount 量线、回忆种子伪记录禁入。
- 不全局提高长间隔权重。清晨锚点仍只看清晨出发的短间隔。

## Decisions

### D1 三级样本集，同档优先

1. 起点桶等于锚点桶，且条数 ≥ 2：这些样本桶权重一律 1.0，再乘既有时间衰减，取加权中位。相邻与更远桶不进入。
2. 否则起点桶与锚点桶相同或相邻，且条数 ≥ 2：桶权重仍为同档 1.0、相邻 0.6，再乘时间衰减。
3. 否则全桶、桶权重 1.0（现有 `strictBuckets: false`），条数 ≥ 2 则取加权中位。
4. 否则维持种子间隔（须有真 `lastAt`，含缓存回退）或不可预测。

理由：要加强的是「从这个钟点出发的下一段」，不是所有 12 小时样本。同档选举里过夜一天一条就是全部，不必再和白天比票数。只把 0.2 再调低仍然会被多条相邻短间隔（0.6）压过，所以同档足够时相邻档也不进场。

备选：按起点钟点与 `lastAt` 钟点的圆形距离做连续权重。边界更滑，但要新参数。本次沿用六档，同档足够就硬隔离。

### D2 锚点与样本桶定义不变

锚点桶 = 最新真发生 `lastAt` 的时段桶。样本桶 = 间隔起点（上一次发生）的时段桶。发生时刻解析（one/number 用 start，已结束 time 用 end）不变。

### D3 与 lastAt 缓存变更对齐

本 delta 的 Requirement 正文包含 `event-last-at-cache` 已写明的缓存回退与「不得合成伪记录」。实现时同步改该兄弟 delta 里「加权中位数与样本充足」场景，使两份 MODIFIED 在投票范围上一致。后归档任一份都不会把同档优先盖回「同档与相邻一起算」。

## Risks / Trade-offs

- [同档经常只有 1 条，退回相邻或全桶] → 过夜又会被短间隔压过。作息稳定、同一档每天都有起点时同档能攒满 2 条；贴着 18:00 两边跳的作息会掉档。本次不改档边界。
- [同档样本变少，置信度 `samples.length / 7` 下降] → 沿用现有公式，只是分母上的样本换成胜出的那一组。不另调置信度。
- [两份未归档 delta 改同一 Requirement] → 正文按 D3 对齐后再各自校验。
